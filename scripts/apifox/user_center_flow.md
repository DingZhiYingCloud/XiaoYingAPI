# 小影 API 用户中心系统运行流程说明

> 本文档详细说明小影 API 统一认证中心（UAC，User Center）的运行流程、接入方式、签名机制与安全设计，供各子项目接入时参考。

---

## 一、系统概述

小影 API 用户中心是一套**统一认证中心**，为所有子项目提供集中的用户注册、登录、Token 签发与身份验证能力。任何项目（以下简称"子项目"）的注册 / 登录 / 用户验证都必须先经过用户中心完成统一认证。

**核心设计目标：**

- **用户池全局共享**：所有子项目共享同一套用户账号体系，用户无需在每个项目重复注册
- **账号系统分配**：账号由用户中心统一分配（纯数字 6-12 位、全局唯一、不可自定义、不可修改）
- **多验证方式可配**：支持「用户名 + 密码」「邮箱」「手机号」三种注册/登录方式；邮箱 / 手机号走**两步注册**（先验码后发号）与**验证码登录**（免密码），由后台独立开关控制，后续可低成本扩展更多方式（微信 / QQ 等）
- **Token 绑定项目**：登录签发的 Token 绑定签发项目，不同项目的 Token 互不通用
- **签名防篡改**：所有接口调用必须携带 HMAC-SHA256 签名，防止参数篡改与重放攻击（公开配置接口除外）
- **项目级有效期**：Token 默认有效期由各项目在后台独立配置

## 二、核心概念

| 概念 | 说明 |
|------|------|
| **用户（User）** | 全局共享用户池中的一条用户记录。包含账号（account）、用户名（username）、密码（哈希存储）、邮箱（email）及验证状态、手机号（phone）及验证状态、状态（status） |
| **账号（account）** | 系统随机分配的纯数字串，长度 6-12 位，首位不为 0，全局唯一。用户登录凭据之一，不可自定义 |
| **用户名（username）** | 注册时由用户自定义，最长 50 字符。**允许重复**（唯一标识是账号） |
| **邮箱（email）** | 注册时可选绑定，全局唯一；两步注册第一步下发验证邮件，**校验通过后才创建账号**；登录凭验证码免密码 |
| **手机号（phone）** | 注册时可选绑定，全局唯一（中国大陆 11 位纯数字）；两步注册第一步下发短信验证码，**校验通过后才创建账号**；登录凭验证码免密码 |
| **验证方式（AuthMethod）** | 后台配置项，控制某类验证方式是否可用。type（如 email / phone）全局唯一、name 展示名、enabled 开关。新增验证方式只需增加一条配置，无需改动代码结构 |
| **验证记录（UserVerifyRecord）** | 一次验证码/激活链接的发放记录：场景（scene：`register` 两步注册意向 / `login` 登录验证码）、类型（type）、凭证（credential）、验证码（code）、激活标识（token，邮箱）、过期时间（expire_time）、是否已用（is_used）。验证码**一次性使用**、**过期作废**；两步注册意向暂存 username/password_hash，校验通过后才建号 |
| **接入项目（UserApp）** | 经审核注册后获得接入资格的子项目。每个项目拥有独立的 APPID + APPSECRET |
| **APPID** | 项目公开标识，**系统自动生成**（`app_` 前缀 + 28 位随机 hex，共 32 字符），全局唯一，调用接口时携带，创建后固定不可修改 |
| **APPSECRET** | 项目签名密钥，**系统自动生成**（`sk_` 前缀 + 60 位随机 hex，共 63 字符），仅项目方与用户中心知晓，用于 HMAC-SHA256 签名，创建后固定。**严禁泄露** |
| **Token** | 登录成功后签发的身份凭证，绑定"用户 + 项目"，有过期时间，可主动注销 |
| **签名参数** | app_id / timestamp / nonce / sign 四个参数，除公开接口外所有用户中心接口必带 |

## 三、系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                        小影 API 管理后台                       │
│   · 注册接入项目（分配 APPID + APPSECRET）                     │
│   · 配置项目 Token 有效期、启停项目                            │
│   · 封禁 / 解封用户，查看 Token 使用情况                        │
│   · 认证方式配置：独立开关邮箱 / 手机号等验证方式（AuthMethod）  │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                     用户中心 API 层                           │
│   · POST /api/user_center/users/register    用户注册（两步注册第一步） │
│   · POST /api/user_center/users/login/send  发送登录验证码             │
│   · POST /api/user_center/users/login       用户登录（验证码/账号+密码） │
│   · POST /api/user_center/users/logout      用户退出          │
│   · GET  /api/user_center/users/info        获取用户信息       │
│   · POST /api/user_center/users/verify      验证 Token        │
│   · POST /api/user_center/users/verify/email          邮箱验证码完成两步注册 │
│   · GET  /api/user_center/users/verify/email          邮箱激活链接（公开）│
│   · POST /api/user_center/users/verify/email/resend   重发邮箱验证邮件 │
│   · POST /api/user_center/users/verify/phone          手机号验证码完成两步注册 │
│   · POST /api/user_center/users/verify/phone/send     发送手机号短信验证码 │
│   · GET  /api/user_center/users/methods      可用注册/登录方式（公开） │
│   · GET  /api/user_center/projects/info     查询项目信息       │
│   每层统一：① 签名校验 → ② 参数校验 → ③ 业务处理 → ④ 统一响应   │
└──────────────▲──────────────────┬───────────────────────────┘
               │                  │
               │ 签名请求          │ 签名请求
        ┌──────┴──────┐   ┌───────▼───────┐
        │   子项目 A    │   │   子项目 B     │
        │ (APPID_A)   │   │  (APPID_B)    │
        └─────────────┘   └───────────────┘
```

> 标注「公开」的接口（methods、邮箱激活链接）免签名、免 Token，其余接口均需签名。

## 四、运行流程详解

### 4.1 子项目接入流程（前置条件）

任何子项目**必须先接入，才能调用用户中心接口**。

```
步骤 1：子项目方向小影 API 管理员提交接入申请
步骤 2：管理员在后台「接入项目」中创建项目，填写项目名称（全局唯一，不可重复）
步骤 3：系统自动生成唯一的 APPID + APPSECRET（无需手动输入），发放给项目方
步骤 4：项目方确认 Token 默认有效期（默认 7 天，后台可调）
步骤 5：项目方开始调用用户中心接口
```

**密钥自动生成说明：**

- APPID / APPSECRET 由用户中心系统自动生成，**管理员无需也不能手动输入**
- APPID 格式：`app_` + 28 位随机 hex（共 32 字符）
- APPSECRET 格式：`sk_` + 60 位随机 hex（共 63 字符）
- 两者均全局唯一，创建后**固定不可修改**（后台保存时强制保留原值，防止误改导致已接入子项目全部失效）
- 应用名称（name）全局唯一：重复名称创建将被拒绝

**接入后项目方应妥善保管：**

| 凭证 | 格式 | 用途 | 保密级别 |
|------|------|------|----------|
| APPID | `app_` + 28 位随机 hex（32 字符） | 接口调用时公开携带 | 公开 |
| APPSECRET | `sk_` + 60 位随机 hex（63 字符） | 计算签名 | **机密，严禁泄露** |

> 项目停用后（后台 status=false），该项目所有接口调用将直接返回「接入项目已被停用」，已签发的 Token 也随之失效。

### 4.2 用户注册流程（两步注册）

```
用户（通过子项目） ──> 子项目 ──POST /users/register──> 用户中心
              <─ 暂存注册意向，下发验证码（不建号、不发放账号） <─
用户 ──> 子项目 ──POST /users/verify/email|phone──> 用户中心
              <── 校验验证码通过 → 创建账号、发放账号 <──
```

**注册支持三种方式：**

| 方式 | 请求参数 | 说明 |
|------|----------|------|
| 用户名 + 密码 | username + password | 永远可用（兜底方式），**直接建号**，一步完成 |
| 邮箱 | email + password | 需后台启用邮箱方式；**两步注册**：先发验证码暂存意向（不建号）→ 校验通过后才建号 |
| 手机号 | phone + password | 需后台启用手机号方式；**两步注册**：先发短信验证码暂存意向（不建号）→ 校验通过后才建号 |

**两步注册完整流程步骤（邮箱 / 手机号）：**

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 子项目收集凭证与密码 | username（≤50字符）/ email（合法邮箱）/ phone（11 位数字）+ password（6-64字符） |
| 2 | 子项目构造签名参数 | app_id / timestamp / nonce / sign（详见第五章） |
| 3 | 子项目调用注册接口 | 请求体：`application/x-www-form-urlencoded` 表单 |
| 4 | 用户中心校验签名 | 失败返回 20011（签名参数缺失 / 过期 / 不匹配 / 项目未注册或停用） |
| 5 | 用户中心校验参数 | 三种凭证全缺→20001；username 超长 / email 格式非法 / phone 非 11 位 / password 长度不符→20002 |
| 6 | 校验方式开关 | 提供 email 但邮箱方式未启用→20002「邮箱注册方式未启用」；phone 同理 |
| 7 | 校验凭证唯一 | 邮箱 / 手机号**全局唯一**：已被其他用户绑定→20002「已被注册」；已存在未完成注册意向→20002「已发起注册，请先完成验证」 |
| 8 | 密码加密暂存 | PBKDF2 加盐哈希（`make_password`），与用户名一起**暂存于注册意向**（不落用户表） |
| 9 | 生成注册批次 | 同一次注册请求（同时绑定邮箱+手机号）共享批次，完成注册时合并为**同一账号** |
| 10 | 发送验证码并暂存意向 | 邮箱→发验证邮件（含验证码+激活链接）；手机号→发短信验证码。**不创建用户、不发放账号** |
| 11 | 返回结果 | 返回 `{username?, email?/phone?, need_verify: true, verify_email_sent?/verify_phone_sent?}`（**无 user_id / account**） |
| 12 | 客户端提交验证码 | 调用 `POST /users/verify/email|phone`（或点击邮件激活链接），提交收到的验证码 |
| 13 | 校验验证码 | 验证码错误 / 过期 / 已使用→20003；原子消费（一次性，并发仅一次成功） |
| 14 | 创建账号、发放账号 | 校验通过后创建用户（绑定凭证并标记已验证），生成 6-12 位纯数字账号；**至此才发放账号** |
| 15 | 返回结果 | 返回 `{user_id, account, username, email?/phone?, email_verified?/phone_verified?}` |

**纯用户名注册（无验证码场景）**：步骤 1-5 校验后直接生成账号、创建用户，一步完成，返回 `{user_id, account, username}`。

**用户名注册成功响应示例：**

```json
{
  "code": 10000,
  "msg": "注册成功",
  "data": {
    "user_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "account": "837120465",
    "username": "test_user"
  }
}
```

**手机号两步注册第一步响应示例（暂存意向，不建号）：**

```json
{
  "code": 10000,
  "msg": "验证信息已发送，请完成验证后发放账号",
  "data": {
    "username": "手机用户",
    "phone": "13800138000",
    "need_verify": true,
    "verify_phone_sent": true
  }
}
```

> 注意：此时**尚未创建账号**，data 中**没有 user_id / account**。客户端应引导用户输入短信验证码，调用 `verify/phone` 完成校验后才会创建账号、发放账号。

**手机号两步注册第二步响应示例（校验通过才建号）：**

```json
{
  "code": 10000,
  "msg": "注册成功",
  "data": {
    "user_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "account": "837120465",
    "username": "手机用户",
    "phone": "13800138000",
    "phone_verified": true
  }
}
```

**要点：**
- **先验码、后发号**：两步注册第一步只下发验证码、暂存意向，**不创建账号**；只有验证码校验通过后系统才创建账号、发放账号
- 同时绑定邮箱 + 手机号时共享一个注册批次：任一凭证先校验通过即建号，另一凭证校验通过后**合并到同一账号**（不重复建号）
- 注册**不签发 Token**，用户需调用登录接口获取 Token
- 用户名允许重复（相同用户名可对应不同账号），系统不以此为唯一标识；**邮箱 / 手机号不允许重复**
- 显式提供 email / phone 但格式非法时**拒绝注册**（不静默降级），避免用户误以为已绑定
- 验证邮件 / 短信发送失败不影响注册意向提交，可通过重发接口（4.10 / 4.12）再次获取

### 4.3 用户登录流程

```
用户 ──> 子项目 ──POST /users/login/send──> 用户中心（邮箱/手机号：先下发登录验证码）
              <──────── 验证码已发送 <────────
用户 ──> 子项目 ──POST /users/login──> 用户中心（携带 code 校验通过才签发 Token）
              <──────── Token + 用户信息 <────────
```

**支持两种登录方式：**

| 方式 | 参数 | 可用条件 |
|------|------|----------|
| 邮箱 / 手机号（验证码登录，免密码） | email 或 phone + code | 对应方式已启用；**需先调用 login/send 获取验证码**，校验通过后才签发 Token |
| 账号 + 密码 | account + password | 永远可用（系统分配的数字账号） |

#### 4.3.1 发送登录验证码（POST /users/login/send）

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 子项目收集凭证 | email 或 phone 二选一 |
| 2 | 构造签名参数并调用 | 表单提交 email/phone + 签名参数 |
| 3 | 签名校验 | 失败返回 20011 |
| 4 | 参数校验 | email/phone 全缺→20001；格式非法→20002 |
| 5 | 校验方式开关 | 邮箱方式未启用→20003「邮箱登录方式未启用」；phone 同理 |
| 6 | 查询用户 | 凭证未注册→20003「该邮箱/手机号未注册，请先注册」（**不泄露**用户已注册的信息） |
| 7 | 校验用户状态 | 用户被封禁→20003「账号已被封禁」 |
| 8 | 冷却检查 | **60 秒内重复发送**→20003「发送过于频繁」（防短信/邮件轰炸） |
| 9 | 下发验证码 | 邮箱→发验证邮件（仅验证码，无激活链接）；手机号→发短信验证码。验证码有效期同注册（邮箱 30 分钟 / 手机号 5 分钟，后台可配） |
| 10 | 返回结果 | 成功返回 code=10000，data 为 null |

#### 4.3.2 登录（POST /users/login）

**邮箱 / 手机号验证码登录（免密码）：**

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 子项目收集凭证 + 验证码 | email 或 phone + code（登录验证码） |
| 2 | 构造签名参数并调用 | 表单提交 email/phone/code + 签名参数 |
| 3 | 签名校验 | 失败返回 20011 |
| 4 | 参数校验 | 凭证全缺→20001；缺少 code→20001「请先通过登录发码接口获取」 |
| 5 | 校验方式开关 | 邮箱方式未启用→20011「邮箱登录方式未启用」；phone 同理 |
| 6 | 查询用户 | 凭证未注册→20011「该邮箱/手机号未注册，请先注册」 |
| 7 | 校验用户状态 | 用户被封禁→20011「账号已被封禁」 |
| 8 | 校验验证码 | 无记录→20011「验证码不存在或已使用」；已过期→20011「验证码已过期」；错误→20011「验证码错误」；**原子消费**（一次性，并发仅一次成功） |
| 9 | 激活存量未验证凭证 | 存量用户邮箱/手机号未验证时，登录校验通过即**同步置为已验证**（激活 + 登录一步完成） |
| 10 | 签发 Token | 生成 64 位 hex 随机 Token，绑定（用户, 项目, 过期时间） |
| 11 | 返回结果 | 返回 `{user_id, account, username, email?, phone?, token, expire_time}` |

**账号 + 密码登录（永远可用）：**

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 子项目收集账号 + 密码 | account + password |
| 2 | 构造签名参数并调用 | 表单提交 account/password + 签名参数 |
| 3 | 签名校验 | 失败返回 20011 |
| 4 | 参数校验 | account 缺失 / password 缺失→20001 |
| 5 | 查询用户 | 按账号查询全局用户池；不存在或密码错误→20011「账号或密码错误」（统一提示，防账号枚举） |
| 6 | 校验密码与状态 | **先校验密码**再校验用户状态（防凭证枚举）；用户被封禁→20011「账号已被封禁」 |
| 7 | 签发 Token | 生成 64 位 hex 随机 Token，绑定（用户, 项目, 过期时间） |
| 8 | 返回结果 | 返回 `{user_id, account, username, token, expire_time}` |

**手机号验证码登录成功响应示例：**

```json
{
  "code": 10000,
  "msg": "登录成功",
  "data": {
    "user_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "account": "837120465",
    "username": "手机用户",
    "phone": "13800138000",
    "token": "5f4dcc3b5aa765d61d8327deb882cf99e6a3c8a4b1f9e2d4c6a8b0c1d2e3f4a5",
    "expire_time": "2026-09-06 12:00:00"
  }
}
```

**安全要点：**
- **验证码登录免密码**：邮箱 / 手机号登录凭验证码即可，不需要密码；验证码**一次性使用**，校验通过后才签发 Token
- **先发码、后登录**：邮箱 / 手机号登录必须先经 `login/send` 下发验证码，登录时携带 code 校验，**校验通过才下发 Token**
- 账号/密码错误时**统一提示**「账号或密码错误」，不暴露凭证是否存在（防账号枚举）；验证码登录对"未注册凭证"明确提示先注册（无 Token 可签发，无需隐藏）
- **关闭方式=彻底停用**：后台关闭某方式后，存量用户也不能再用该方式登录（登录同样受 AuthMethod 开关拦截）
- Token 只绑定当前项目：同一用户在不同项目登录会得到**不同**的 Token，且不能跨项目使用
- 支持多端并存：同一用户在同一项目可同时持有多个有效 Token（并发数由子项目自行控制）
- Token 过期时间以服务器时间为准，返回格式 `yyyy-MM-dd HH:mm:ss`

### 4.4 验证 Token 流程（子项目核心调用）

子项目在每次需要确认用户身份时（如访问受保护资源），调用验证接口。

### 4.8 认证方式配置（后台开关）

管理后台「认证方式配置」（AuthMethod）集中控制各类验证方式是否可用，是邮箱 / 手机号等验证方式的**总开关**。

| 配置项 | 说明 |
|--------|------|
| type | 验证方式类型，全局唯一（当前：`email` 邮箱、`phone` 手机号；未来扩展如 `wechat` 直接新增一行） |
| name | 展示名称 |
| enabled | 是否启用（true 启用 / false 关闭） |

**开关规则：**

| 后台状态 | 注册 | 登录 |
|----------|------|------|
| 仅启用 email | 邮箱两步注册可用；手机号注册拒绝（20002 未启用） | 邮箱验证码登录可用；手机号登录拒绝 |
| 仅启用 phone | 手机号两步注册可用；邮箱注册拒绝 | 手机号验证码登录可用；邮箱登录拒绝 |
| email + phone 均启用 | 两种方式均可，客户端二选一 | 两种方式均可 |
| 全部关闭 | 仅用户名 + 密码注册（永远可用） | 仅账号 + 密码登录 |

**客户端感知流程：**

```
客户端进入注册/登录页
        │
        ▼
GET /api/user_center/users/methods（公开，免签名）
        │
        ▼
返回 {"methods": ["email", "phone"], "username": true}
        │
        ▼
客户端按启用的方式渲染入口（二选一 / 仅用户名+密码）
```

- `methods`：当前启用的验证方式类型列表；空列表表示仅支持用户名 + 密码
- `username`：用户名 + 密码方式是否可用（永远为 true，作为兜底方式）
- 关闭方式 = **彻底停用**：存量用户也不能再用该方式注册新账号或登录，防止方式关闭后仍有通道

### 4.9 邮箱验证码完成注册流程（两步注册第二步）

注册提交了邮箱后，需校验邮箱验证码 / 激活链接，**校验通过后才创建账号、发放账号**。提供两种方式：

**方式一：验证码校验（POST，需签名）**

```
子项目 ──POST /users/verify/email {email, code, 签名参数}──> 用户中心
              <── {user_id, account, username, email, email_verified} <──
```

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 用户从验证邮件中获取 6 位验证码 | 验证码有效期默认 30 分钟（后台 EMAIL_VERIFY_EXPIRE_MINUTES 可配） |
| 2 | 子项目调用校验接口 | 表单：email + code + 签名参数 |
| 3 | 校验 | 无注册意向→20003「未找到注册意向，请先提交注册」；验证码错误 / 已过期 / 已使用→20003 |
| 4 | 原子消费验证码 | 验证码**一次性使用**，并发重复提交只有一个成功 |
| 5 | 创建账号、发放账号 | 校验通过后创建用户（绑定邮箱并标记已验证），生成 6-12 位纯数字账号 |
| 6 | 返回结果 | 返回 `{user_id, account, username, email, email_verified}` |

**方式二：激活链接（GET，公开免签名）**

```
用户邮箱中点击激活链接
        │
        ▼
GET /users/verify/email?token=xxx（浏览器直接访问，公开接口）
        │
        ▼
校验 token → 创建账号、发放账号 → 页面提示注册成功
```

验证邮件中同时包含 6 位验证码与激活链接（形式由后台 EMAIL_VERIFY_MODE 配置控制），用户任选其一完成校验。同一次注册同时绑定邮箱 + 手机号时，两个凭证共享注册批次：任一凭证先校验通过即建号，另一凭证校验通过后**合并到同一账号**（不重复建号）。

## 五、签名机制（重要）

除**公开接口**（GET /users/methods、GET /users/verify/email?token=xxx）外，所有用户中心接口调用都必须携带 4 个签名公共参数，用于**身份识别 + 防篡改 + 防重放**。

### 5.1 签名公共参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| app_id | string | 是 | 项目 APPID（后台自动生成，`app_` 前缀） |
| timestamp | string | 是 | 10 位时间戳（秒），与服务器时间差须在 ±5 分钟内 |
| nonce | string | 是 | 随机字符串，每次请求唯一（建议 16+ 位随机 hex） |
| sign | string | 是 | 签名值（64 位小写 hex） |

### 5.2 签名算法（HMAC-SHA256）

```
1. 取除 sign 外的所有参数（含 app_id / timestamp / nonce / 业务参数）
2. 按键名 ASCII 升序排序
3. 拼接为 key=value&key=value&...
4. 以 app_secret 为密钥做 HMAC-SHA256
5. 输出小写 hex 字符串即为 sign
```

### 5.3 Python 签名示例

```python
import hashlib, hmac, time, secrets, urllib.parse

def build_sign(params: dict, app_secret: str) -> str:
    """生成签名（小写 hex）"""
    items = sorted((k, str(v)) for k, v in params.items()
                   if k != 'sign' and v not in (None, ''))
    raw = '&'.join(f'{k}={v}' for k, v in items)
    return hmac.new(app_secret.encode(), raw.encode(), hashlib.sha256).hexdigest()

# 手机号验证码登录示例（邮箱/手机号登录免密码：先调 login/send 发码，再带 code 校验通过才签发 Token）
params = {
    'app_id': 'app_5f3a9c2b7e6d8f1a2b3c4d5e6f7a8b9c',
    'timestamp': str(int(time.time())),
    'nonce': secrets.token_hex(8),
    'phone': '13800138000',
    'code': '482913',
}
params['sign'] = build_sign(params, 'sk_9c8b7a6f5e4d3c2b1a0f9e8d7c6b5a4f0e1d2c3b4a596877')

# 发送请求（表单）
url = 'https://your-domain/api/user_center/users/login'
body = urllib.parse.urlencode(params)
```

### 5.4 安全校验规则

| 校验项 | 失败返回 |
|--------|----------|
| 四个签名参数必须同时提供 | 20011 签名参数缺失 |
| timestamp 必须为数字 | 20011 参数格式错误: timestamp 必须为 10 位时间戳(秒) |
| timestamp 与服务器时间差 ≤ ±5 分钟 | 20011 签名过期: timestamp 超出有效窗口(±5分钟) |
| app_id 必须已注册 | 20011 未注册的接入项目: app_id 不存在 |
| 项目必须处于启用状态 | 20011 接入项目已被停用 |
| sign 必须与本地计算一致（常数时间比较，防时序攻击） | 20011 签名校验失败: sign 不匹配 |

**防重放说明：**
- timestamp 窗口（±5 分钟）+ nonce 唯一性：同一 nonce 在窗口内重复使用会被识别
- 校验使用 `hmac.compare_digest` 常数时间比较，防止时序侧信道攻击
- 建议子项目每次请求都生成全新 nonce

## 七、安全设计要点

1. **密码安全**：PBKDF2 加盐哈希存储，永不存储明文；账号登录统一错误提示防账号枚举
2. **签名防篡改**：HMAC-SHA256 覆盖全部业务参数，任何参数被修改都会导致签名校验失败
3. **重放防护**：timestamp ±5 分钟窗口 + nonce 唯一性
4. **Token 隔离**：Token 绑定项目，跨项目不可用；伪造 / 超长 / 未知 Token 一律按无效处理
5. **状态联动**：用户封禁 → 该用户所有 Token 立即失效；项目停用 → 该项目所有 Token 失效
6. **先验码、后发号**：两步注册第一步只发验证码、暂存意向，**不创建账号**；验证码校验通过后才创建账号、发放账号
7. **验证码一次性**：验证码 / 激活链接**原子消费**（并发重复提交仅一次成功），使用后即失效
8. **验证码时效**：邮箱验证码默认 30 分钟、手机验证码默认 5 分钟过期，过期作废需重新发送
9. **发送冷却**：验证邮件 / 短信发送（注册意向重发、登录发码）有 **60 秒冷却**（按"验证方式 + 凭证"全局生效），防止邮件 / 短信轰炸
10. **防凭证枚举**：账号登录先验密码再验状态，错误密码统一提示；邮箱/手机号验证码登录必须先发码再登录，验证码一次性
11. **方式开关联动**：关闭某验证方式后，注册与登录**同时**停用（含存量用户），杜绝绕过通道
12. **接口方法限制**：注册 / 登录 / 退出 / 验证 / 发送类接口仅允许 POST，信息查询仅允许 GET，违规返回 405
13. **传输安全**：建议全站 HTTPS，防止请求参数与 Token 在传输中被窃听
14. **密钥管理**：APPSECRET 严禁写入前端代码 / 提交到仓库，子项目后端保管

## 九、典型接入时序（完整示例）

以下演示子项目"视频分析站"接入用户中心的完整调用序列（以手机号两步注册 + 验证码登录为例，邮箱注册流程同理）：

```
① 接入：小影管理员后台创建项目「视频分析站」，系统自动生成并发放
   APPID = app_5f3a9c2b7e6d8f1a2b3c4d5e6f7a8b9c
   APPSECRET = sk_9c8b7a6f5e4d3c2b1a0f9e8d7c6b5a4f0e1d2c3b4a596877

② 客户端获取可用方式（登录 / 注册页渲染前）：
   客户端 GET /users/methods（公开，免签名）
   ← 返回 {methods: ["email", "phone"], username: true}
   客户端渲染「邮箱 / 手机号 / 用户名+密码」入口

③ 用户手机号注册（两步注册第一步：发码暂存意向，不建号、不发放账号）：
   子项目表单提交 {phone: "13800138000", password: "abc123", app_id, timestamp, nonce, sign}
   ← 返回 {username: "手机用户", phone: "13800138000", need_verify: true, verify_phone_sent: true}
     （注意：此时没有 user_id / account，账号尚未创建）
   子项目提示用户输入短信验证码

④ 用户输入短信验证码，子项目提交校验（两步注册第二步：校验通过才建号）：
   子项目表单提交 {phone: "13800138000", code: "482913", app_id, timestamp, nonce, sign}
   ← 返回 {user_id, account: "837120465", username: "手机用户",
           phone: "13800138000", phone_verified: true}
   此时系统才创建账号，子项目展示「您的账号为：837120465，请妥善保管」

⑤ 用户登录（邮箱/手机号为验证码登录，免密码）：
   子项目先 POST /users/login/send {phone: "13800138000", 签名参数}
   ← 返回 code=10000（短信验证码已下发）
   用户输入登录验证码 → 子项目 POST /users/login {phone: "13800138000", code: "530271", 签名参数}
   ← 返回 {user_id, account, username, phone, token, expire_time}
   子项目将 token 返回给用户端（前端）保存

⑥ 用户访问受保护功能（如发起视频分析）：
   用户携带 token 请求子项目 → 子项目 POST /users/verify {token, 签名参数}
   ← 返回 {valid: true, user_id, account, username, phone, phone_verified}
   子项目确认身份后放行，将 user_id 与业务数据关联

⑦ 用户退出登录：
   用户点击退出 → 子项目 POST /users/logout {token, 签名参数}
   ← 返回 code=10000
   该 token 立即失效
```

**邮箱注册 / 登录的差异步骤：**
- 注册第一步传 `email` 而非 `phone`，成功后返回 `verify_email_sent`
- 第二步二选一：调用 `POST /users/verify/email` 提交验证码，或用户点击邮件内激活链接（`GET /users/verify/email?token=xxx`，浏览器直接访问），校验通过后才建号
- 登录先调 `POST /users/login/send`（传 `email`）下发验证码，再调 `POST /users/login` 带 `code` 完成登录
- 同时绑定邮箱 + 手机号注册时，两个凭证共享注册批次，完成校验后合并为**同一账号**

## 十、常见问题（FAQ）

**Q1：用户名可以重复吗？**
可以。用户唯一标识是系统分配的账号（account），用户名允许重复，不同用户可同名。

**Q2：账号能自己改吗？**
不能。账号由系统随机分配（纯数字 6-12 位、全局唯一），不可自定义、不可修改。

**Q3：忘记账号怎么办？**
账号在注册完成（验证码校验通过建号）后由系统返回，建议子项目在建号成功页面向用户明确展示并提示保存。用户也可使用已绑定的邮箱或手机号验证码登录（需已启用）。

**Q4：Token 有效期如何配置？**
在管理后台「接入项目」中修改该项目 token_expire_days（默认 7 天），修改后新签发的 Token 按新配置生效。

**Q5：用户被封禁后，已签发的 Token 会怎样？**
立即失效。该用户的所有 Token（所有项目）在验证 / 信息接口均返回失效。

**Q6：项目被停用后，已签发的 Token 会怎样？**
该项目的所有接口调用（含签名层）直接返回「接入项目已被停用」，Token 随之失效。

**Q7：签名计算时哪些参数要参与？**
除 sign 自身外，所有请求参数（app_id、timestamp、nonce 以及业务参数）都要参与排序与拼接，缺失任何一个都会导致签名不匹配。

**Q8：timestamp 为什么不能用本地时间？**
服务器校验时与服务器时间比对（±5 分钟）。子项目应使用服务器下发的标准时间或 NTP 校时，避免客户端时钟偏差导致签名过期。

**Q9：注册提交了邮箱/手机号后，为什么还没有账号？**
邮箱 / 手机号走**两步注册**：第一步只下发验证码、暂存注册意向，**不会创建账号**。只有第二步提交验证码并校验通过后，系统才创建账号、发放账号（账号在此时才生成并返回）。

**Q10：验证码有效期多久？发错/过期了怎么办？**
邮箱验证码默认 30 分钟、手机短信验证码默认 5 分钟（后台可配）。注册验证码过期或未收到可调用重发接口（邮箱 `verify/email/resend`、手机 `verify/phone/send`）；登录验证码过期可重新调用 `login/send` 获取。发送均有 60 秒冷却。

**Q11：验证码会被重复使用吗？**
不会。验证码 / 激活链接**一次性使用**，原子消费（并发重复提交仅一次成功），使用后即失效。

**Q12：邮箱/手机号可以同时注册吗？如何开启或关闭？**
可以在管理后台「认证方式配置」中独立开启 / 关闭邮箱、手机号（及未来的其他方式）。同时开启时客户端二选一；全部关闭时降级为用户名 + 密码。客户端通过 `GET /users/methods`（公开接口）实时获取当前可用方式。

**Q13：后台关闭了邮箱/手机号方式，已绑定的用户还能用吗？**
不能。关闭方式 = 彻底停用，注册与登录（含存量用户）同时拦截，杜绝绕过通道。

**Q14：邮箱/手机号登录需要密码吗？**
不需要。邮箱 / 手机号登录为**验证码登录（免密码）**：先调用 `POST /users/login/send` 下发验证码，再调用 `POST /users/login` 携带 code，校验通过后才签发 Token。只有「账号 + 密码」登录需要密码。
