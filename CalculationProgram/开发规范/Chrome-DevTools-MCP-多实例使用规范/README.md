# Chrome DevTools MCP 多实例使用规范

> **解决什么问题**：多个 agent / 多个编辑器窗口同时使用 Chrome DevTools MCP 时，互相抢同一个 Chrome profile，导致连接失败、行为错乱、截图串台。
> **核心结论**：一个实例 = 一个独立 profile（或各连各的端口）；路径、端口、版本一律用占位符配置，命令里不写死。

## 文件

| 文件 | 说明 |
| --- | --- |
| `Chrome DevTools MCP 多实例使用规范.md` | 完整正文（可在线预览 / 下载）：参数约定 → 三种模式 → 配置示例 → 红线 → 排障 |

## 怎么读

1. 先看第二节「参数约定」，按自己机器填一次（后文全部引用这套参数）；
2. 按场景选模式：互不干扰选 **A（独立 profile）**，复用登录态选 **C（连外部 Chrome）**；
3. 照第四节复制 JSON / 命令；
4. 出问题直接查第九节排障表。

## 适用提示

- 示例为 Windows + PowerShell；Linux / macOS 的差异见正文 2.1。
- 不绑定具体安装路径、端口与版本号：路径以 `npm config get prefix` 为准，参数以 `chrome-devtools-mcp --help` 为准。
- 原文中「本机安装信息」一类与具体机器绑定的内容已移除，替换为任何人都能复跑的自检命令。
