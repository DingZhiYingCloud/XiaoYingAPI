# 多语言开发指南（i18n）

本文件说明官网前端的多语言机制，以及**新增文案**、**新增语言**时的标准操作步骤。
适用目录：`locale/`、`API/templates/`、`API/static/js/site/`、`API/website/`。

---

## 一、机制概览

**源语言是简体中文**：代码里直接写中文字符串，这个中文字符串本身就是 gettext 的 `msgid`，
译文放在各语言的 `.po` / `.mo` 里。因此新增文案时**不需要**改成英文再翻译，照常写中文即可。

| 层面 | 写法 | 词条进入哪个域 | 运行时由谁翻译 |
|---|---|---|---|
| HTML 模板 | `{% trans "中文" %}` / `{% blocktrans %}` | `django` | 模板引擎 |
| 前端 JS | `gettext('中文')` / `interpolate(gettext('…%(x)s…'), {...}, true)` | `djangojs` | 浏览器（脚本从 `/jsi18n/` 获取词典） |
| 后端 Python | `gettext as _` → `_('中文')` | `django` | Django 视图/模型层 |
| API 文档内容 | 声明式数据保持中文原样，**不写** `_()` | `django` | 渲染前由 `localize()` 翻译副本 |

语言选择流程：

```
点击页头「语言」下拉 → /lang/?lang=zh-hant&next=/docs/
  → views.set_language 校验语言码、写入 Cookie（xyapi_language）、回跳干净地址
  → 后续请求由 LocaleMiddleware 读 Cookie 激活语言（无 Cookie 时看 Accept-Language）
```

目录结构：

```
locale/
├─ en/            LC_MESSAGES/{django.po, django.mo, djangojs.po, djangojs.mo}
├─ zh_Hant/       LC_MESSAGES/{django.po, django.mo, djangojs.po, djangojs.mo}   ← 由脚本生成
└─ （zh-hans 无需目录：找不到译文时 gettext 直接返回 msgid，也就是简体原文）
scripts/
├─ compile_locale.py   把 .po 编译成 .mo（本机无 gettext/msgfmt，故用纯 Python 实现）
└─ make_zh_hant.py     把简体词条转成繁体词条（仅字形转换）
```

## 二、新增一条文案（最常用）

以「给某个页面加一句提示」为例：

**① 在代码里用中文写，并加上翻译标记**

- 模板：[headers.html](../API/templates/common_html/headers.html) 顶部已有 `{% load static i18n %}`，直接用：
  ```django
  <p>{% trans "仅保存在本机浏览器" %}</p>
  ```
  含模板变量时用 `{% blocktrans %}`：
  ```django
  {% blocktrans with n=services|length %}共 {{ n }} 项服务{% endblocktrans %}
  ```
- 前端 JS（`API/static/js/site/*.js`）：
  ```js
  alert(gettext('网络异常，请稍后重试'));
  // 含插值：用 interpolate，占位符写成 %(name)s
  interpolate(gettext('请求失败（HTTP %(code)s）'), { code: 500 }, true);
  ```
- 后端：`from django.utils.translation import gettext as _`，然后 `_('非法的状态值')`。

**② 在英文词条表里补上译文**

打开 [django.po](../locale/en/LC_MESSAGES/django.po)（服务端文案）
或 [djangojs.po](../locale/en/LC_MESSAGES/djangojs.po)（前端 JS 文案），
在对应分组追加：

```
msgid "仅保存在本机浏览器"
msgstr "Stored locally only"
```

> `msgid` 必须与代码里的字符串**一字不差**（含空格、全角标点）。写错不会报错，
> 只会静默回退成中文原文。

**③ 生成繁体词条 + 编译**

```powershell
.venv\Scripts\python.exe scripts\make_zh_hant.py     # 重新生成 locale/zh_Hant 的 .po
.venv\Scripts\python.exe scripts\compile_locale.py   # 把所有 .po 编译成 .mo
```

**④ 重启开发服务器**

Django 6 默认在进程内缓存模板，改了模板必须重启才生效：

```powershell
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8010 --noreload
```

**⑤ 验证**：用页头语言下拉切到 English / 繁體中文，确认新文案已翻译、且没有回退显示中文。

## 三、新增一门语言

以新增「日语 `ja`」为例：

1. **登记语言**（[settings.py](../XiaoYingAPI/settings.py#L107-L111)）：
   ```python
   LANGUAGES = [
       ('zh-hans', '简体中文'),
       ('zh-hant', '繁體中文'),
       ('en', 'English'),
       ('ja', '日本語'),      # 新增
   ]
   ```
   页头下拉会自动多出这个选项，无需改模板。

2. **建词条文件**（注意目录名规则，见下方「坑」第 1 条）：
   ```
   locale/ja/LC_MESSAGES/django.po       ← 服务端文案译文
   locale/ja/LC_MESSAGES/djangojs.po     ← 前端 JS 文案译文
   ```
   这两个文件是**纯文本**，可直接复制 `locale/en/` 下的同名文件，把 `msgstr` 换成日语即可
   （`msgid` 保持简体中文不动，分组注释也可保留）。文件头不必手写，编译脚本会自动生成。

3. **编译并重启**：
   ```powershell
   .venv\Scripts\python.exe scripts\compile_locale.py
   ```

4. **验证**：切到该语言，抽查首页 / `/docs/` / `/docs/email/` / 登录注册页。

> 若某种语言只想先上一部分（例如先不做前端 JS），可以只建 `django.po`，
> 未翻译的地方会自动回退成中文原文，不会报错。

## 四、容易踩的坑（务必看）

1. **locale 子目录名不是语言码本身，而是 `to_locale()` 形式**
   语言码里的连字符要换成下划线、地区首字母大写：`zh-hant` → **`zh_Hant`**，
   `zh-hans` → `zh_Hans`，`pt-br` → `pt_BR`。
   写成 `locale/zh-hant/` 的话 Django 找不到 `.mo`，页面会一直是简体，而且**不报任何错**
   （这是本项目实际踩过的坑）。

2. **改完 `.po` 必须编译成 `.mo`**
   Django 运行时只读 `.mo`，`.po` 只是给人看的源文件。忘了跑 `compile_locale.py`
   就会出现「改了没生效」。

3. **本机没有 gettext**，所以：
   - 不能用 `manage.py makemessages`（依赖 `xgettext`）自动抽取文案，需要**手工**往 `.po` 补条目；
   - 不能用 `manage.py compilemessages`（依赖 `msgfmt`），请用 `scripts/compile_locale.py`。

4. **`{# … #}` 注释只能写在一行**
   跨行的 `{# … #}` 不会被解析掉，会**原样渲染成页面文本**并把布局撑坏。
   需要多行注释请用 `{% comment %}…{% endcomment %}`。

5. **不要对模块级常量调用 `_()`**
   `services.py` 的 `SERVICES`、`docs/*.py` 的 `SERVICE` 都是模块导入时构造的常量。
   若在声明处写 `_('中文')`，译文会被「首次请求的语言」永久固化（之后切换语言不生效）。
   正确做法：保持中文原样，在渲染前调用
   [services.localize()](../API/website/services.py#L105-L115) /
   [docs.localize()](../API/website/docs/__init__.py#L71-L92)
   翻译**副本**。新增类似的声明式数据时请沿用这个模式。

6. **前端 JS 的词条走 `djangojs` 域**
   JS 里用 `gettext()` 取词，它由 `/jsi18n/`（Django `JavaScriptCatalog`）下发。
   词条要写进 `djangojs.po`，写到 `django.po` 里对 JS 无效。

7. **品牌名不翻译**
   logo 与 `小影API` 品牌标识保持原样；出现在句子里的才按 `XiaoYingAPI` 翻译。

8. **语言名称显示为本族语写法**
   页头下拉用 `name_local`（`简体中文` / `繁體中文` / `English`），不随当前语言变化，
   所以 `LANGUAGES` 里的中文名不参与显示。

9. **繁体是脚本生成的，别手改**
   `locale/zh_Hant/**` 由 [make_zh_hant.py](../scripts/make_zh_hant.py)
   覆盖生成（词条 = 简体原文转字形），手工改动会在下次生成时丢失。
   转换用的是纯 Python 库 `zhconv` 的 `zh-hant`（通用繁體，不同地区用词），
   并在脚本内的 `POST_FIX` / `KEEP_QIAN` 里校正了它给错的字形，例如：
   签名（不是「籤名」）、為（不是异体「爲」）、啟、偽、裡。
   若发现其它用字问题（或要改成台湾/香港用词，如 軟體/專案/影片），
   请改这两个表，或直接改为人工维护并停用该脚本。

10. **生产部署记得 `collectstatic`**
    静态资源（含 JS）由 `STATIC_ROOT` 提供；改过 `API/static/js/site/*.js` 后
    上线前必须收集静态文件。

## 五、验证清单

改完文案 / 加完语言后，建议按这个清单过一遍：

- [ ] `python manage.py check` 无报错
- [ ] 所有模板能被解析：逐个页面打开一次（改过 `{% blocktrans %}` 时尤其要开）
- [ ] 页面文本里没有 `{#`、`%}`、`{{` 之类的模板标记泄漏
- [ ] 三种语言各切一遍：页头导航、首页卡片、`/docs/` 左侧菜单、`/docs/email/` 参数说明
- [ ] 切换语言后地址栏不带 `lang=` 参数，刷新后语言被记住
- [ ] 浏览器控制台无 `gettext is not defined` 之类的 JS 报错
- [ ] 页头高度正常（若注释写错行，页头会被泄漏的文本撑高）
