# 宝塔搭建好之后的初始化指南

## 〇、使用说明（给 AI）

- 本文档是"宝塔面板新装 → 环境初始化 → 部署小影API项目"的完整操作手册。
- 文中所有 `${占位符}` 均为**待确认信息**，执行前必须先向用户提问确认，由用户提供真实值后再继续，禁止自行假设。
- 每个阶段均附【验证点】，必须通过验证后才进入下一阶段。

## 一、初始化前的信息确认

| # | 待确认项 | 占位符 | 用途 |
|---|----------|--------|------|
| 1 | 服务器 IP / OS / 宝塔版本 | `${服务器IP}` | 确认登录与面板环境 |
| 2 | 项目部署路径 | `${项目部署路径}` | 代码存放位置 |
| 3 | 虚拟环境名称 / Python 版本 | `${虚拟环境名}` | 隔离 Python 依赖 |
| 4 | 对外域名 | `${域名}` | Nginx server_name / ALLOWED_HOSTS |
| 5 | uwsgi 监听端口 | `${端口}` | 后端服务端口 |
| 6 | 运行用户 | `${运行用户}` | uwsgi uid/gid（通常 www） |
| 7 | 代理数据文件相对路径（含大小写） | `${代理JSON路径}` | 业务接口读取文件 |
| 8 | 是否需要 HTTPS / 域名解析是否已指向本机 | - | 影响 Nginx 配置 |

> 以上任一信息缺失，**停下并提问**，不得自行假设。

## 二、环境初始化（宝塔全新环境）

### 2.1 背景

宝塔面板为新装，服务器上没有任何 Python 运行环境，需先由 AI 完成环境初始化，再部署项目。

### 2.2 初始化流程

```text
[步骤1] 确认系统信息
   → 确认 OS 版本、宝塔版本、是否已装 Python 版本管理器
   → 验证点：SSH 登录正常，宝塔面板可访问

[步骤2] 创建项目虚拟环境
   → 用宝塔"Python 项目管理器"创建，或手动 venv 创建
   → 验证点：虚拟环境 bin 目录存在，python --version 正常
   → 【需确认】环境命名（如 ${虚拟环境名}）与 Python 版本

[步骤3] 安装项目依赖
   → 在虚拟环境内执行 pip install -r requirements.txt
   → 验证点：import django 等核心依赖无报错
   → 注意：必须在虚拟环境内安装，禁止污染全局环境

[步骤4] 安装 uwsgi（重点，易失败）
   → 优先 pip install uwsgi；失败则走源码编译（见 4.1）
   → 验证点：uwsgi --version 输出正常
```

### 2.3 通用环境准备（强烈推荐：一次装好，后续项目全部复用）

为避免每个新项目都重复安装 uwsgi / 依赖、且反复踩"找不到 django"的坑，建议在宝塔中只创建**一个通用虚拟环境**，一次性装好通用依赖，后续所有 Django 项目都指向它：

```bash
# 在通用虚拟环境中安装（一次即可，所有项目复用）
${通用虚拟环境bin}/pip install uwsgi
${通用虚拟环境bin}/pip install Django django-cors-headers requests lxml python-dotenv
```

- 新项目部署时，uwsgi.ini 的 `virtualenv` / `pythonpath` 直接指向通用环境即可，无需再装依赖
- 若项目有特殊依赖，再在通用环境中补装
- 验证点：`${通用虚拟环境bin}/uwsgi --version` 正常，`${通用虚拟环境bin}/pip list` 能查到 django
- 运行 uwsgi 若报 `libpython3.12.so.1.0: cannot open shared object file`，按 4.2 用 ldconfig 注册共享库

## 三、项目部署

### 3.1 拉取代码

```bash
# 确认代码来源（git 地址 / 压缩包）【需确认】
cd ${项目部署路径}
# git clone 或解压后，确认 requirements.txt 存在
```

### 3.2 配置 .env

- 检查 `.env` 中 `ALLOWED_HOSTS` 是否包含 `${域名}`（否则访问返回 400）
- 检查业务文件路径（如 `${代理JSON路径}`）是否与实际目录**大小写完全一致**（Linux 区分大小写）
- 修改 `.env` 后必须**完全重启 uwsgi** 才生效（环境变量只在启动时加载）

### 3.3 配置 uwsgi.ini

```ini
[uwsgi]
# 项目目录（【需确认】${项目部署路径}）
chdir = ${项目部署路径}
# WSGI 入口
wsgi-file = ${项目部署路径}/项目名/wsgi.py
callable = application
# 虚拟环境与依赖路径（必须指定，否则用系统 Python 找不到 django）
virtualenv = ${虚拟环境路径}
pythonpath = ${虚拟环境路径}/lib/python3.x/site-packages
# 进程/线程
processes = 4
threads = 2
# pid 文件
pidfile = ${项目部署路径}/uwsgi.pid
# 监听地址（【需确认】端口 ${端口}）
# S-11 安全：生产仅监听回环地址，由本机 Nginx 反代对外，禁止 0.0.0.0 裸监听
http = 127.0.0.1:${端口}
# 运行用户
uid = ${运行用户}
gid = ${运行用户}
master = true
buffer-size = 32768
daemonize = ${日志目录}/uwsgi.log
```

启动命令建议用**绝对路径**，避免依赖 PATH：

```bash
nohup ${虚拟环境bin}/uwsgi --ini ${项目部署路径}/uwsgi.ini &
```

### 3.4 配置 Nginx 反向代理

1. 在宝塔面板「站点 → 反向代理」中添加，指向 `http://127.0.0.1:${端口}`；
2. 宝塔会**自动生成** `location /` 于站点主配置的"HTTP反向代理相关配置开始 >>>"区域；
3. 若项目含长耗时任务（如 DeepSeek 生成），需在该 `location /` 块内追加超时配置（见 4.6）。

> ⚠️ **重要**：宝塔已有 `location /` 后，**禁止**再通过 extension 目录或手动方式新增第二个 `location /`，否则 nginx 报 `duplicate location "/"`（详见 4.6）。

### 3.5 小影API 专属：部署前后必做清单

> 以下 9 步为本项目**专属**必做项，与前面的通用流程配合执行；每步均附【验证点】，未通过不得进入下一步。

| # | 操作 | 命令 / 要点 | 验证点 |
|---|------|-------------|--------|
| 1 | 安装依赖 | `${虚拟环境bin}/pip install -r requirements.txt`（含构建期依赖 `zhconv`） | `pip list` 能查到 django、zhconv 等核心依赖 |
| 2 | 提交前端编译产物 | 改过前端类名/样式时，在本机重编译 `output.css` 并提交（线上不编译） | `API/static/css/output.css` 已是最新且入库 |
| 3 | 提交词条编译产物 | 改过词条时，在本机执行 `python scripts/compile_locale.py` 生成 `.mo` 并提交 | `locale/*/LC_MESSAGES/*.mo` 均为最新且入库 |
| 4 | 收集静态文件 | `python manage.py collectstatic --noinput` | `STATIC_ROOT`（`<项目根>/static`）下出现 `css/output.css` |
| 5 | 执行数据库迁移 | `python manage.py migrate`（迁移文件随代码入库，线上**只 migrate**，禁止线上 `makemigrations`） | `python manage.py showmigrations` 无未应用项 |
| 6 | 重建分类树 | `python manage.py rebuild_category_tree`（**新部署必须执行**；分类树为空时新增服务默认「需要认证」，会导致接口匿名被拒） | 公开接口（如 `/api/captcha_auth/aliyun/config`）可匿名访问；需认证接口不带签名时返回 20011 |
| 7 | 存量凭据回填（按需） | `python manage.py security_backfill`（**仅当**项目含 S-06 存量凭据回填需求时执行一次） | 命令无报错 |
| 8 | 创建超级管理员 | `python manage.py createsuperuser`（首次），超管从 `/login/` 用「账号 + 密码」登录 | 登录成功后页头出现「超级管理员」入口 |
| 9 | 完全重启 uWSGI | `--stop` 后重新 `--ini`（仅 `--reload` 对 `.env` / `.mo` 不生效） | 日志出现 `WSGI app 0 ready`，官网页面可正常访问 |

**必须特别强调的三点：**

1. **编译产物随代码提交，线上不重新生成**：`API/static/css/output.css`、`locale/**/*.mo`、`*/migrations/*.py` 都是**随代码提交的产物**。线上只执行 `collectstatic` / `migrate`，**不重新编译/生成**。
2. **`.mo` / 模板改动后必须完全重启 uWSGI**：Django 会缓存已加载的翻译目录与模板，仅 `--reload` 不生效，必须 `--stop` 后重新 `--ini`。
3. **`SECRET_KEY` 上线后不可变更**：`.env` 中 `SECRET_KEY` 必填（缺失拒绝启动），且**同时用于 app_secret 的密文派生**；一旦变更，已加密的 app_secret 将**全部不可解密**。

> 补充：本项目 `/admin/` 已不存在（`django.contrib.admin` 与 `django-simpleui` 已从 `INSTALLED_APPS` 移除），管理功能由官网超管控制台 `/console/projects/` 接管，别再找 `/admin/`。

## 四、常见问题与修复（FAQ）

### 4.1 nohup: failed to run command 'uwsgi': No such file or directory

**原因**：uwsgi 未安装到当前虚拟环境，或启动命令依赖 PATH 找不到它。

**修复**：
```bash
# 方式一：pip 安装（推荐先试）
${虚拟环境bin}/pip install uwsgi

# 方式二：源码编译（pip 失败时使用）
cd /tmp && wget https://files.pythonhosted.org/packages/.../uwsgi-2.0.28.tar.gz
tar zxf uwsgi-2.0.28.tar.gz && cd uwsgi-2.0.28

# 关键：非交互式 SSH 中 PATH 可能为空，先补齐
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
export CC=/usr/bin/gcc

# 若报 cannot find -lpython3.12，指定 Python 库路径
export LDFLAGS=-L${Python安装目录}/lib

make
cp uwsgi ${虚拟环境bin}/uwsgi && chmod +x ${虚拟环境bin}/uwsgi
```

### 4.2 运行时报 libpython3.12.so.1.0: cannot open shared object file

**原因**：动态库不在系统查找路径中。

**修复**：
```bash
echo "${Python安装目录}/lib" > /etc/ld.so.conf.d/python.conf
ldconfig
```

### 4.3 uwsgi 启动后 ModuleNotFoundError: No module named 'django'

**原因**：uwsgi 用的是系统 Python，未加载虚拟环境。
- ⚠️ 宝塔「Python 项目管理器」生成的 uwsgi.ini 模板**默认没有** `virtualenv` / `pythonpath` 两行，新项目几乎必踩此坑，表现为日志中 `unable to load app 0 ... No module named 'django'`

**修复**：
1. 在 `uwsgi.ini` 中补充 `virtualenv` 和 `pythonpath`（见 3.3），指向已装好 django 的（通用）虚拟环境
2. 完全重启 uwsgi（--stop 后重新 --ini，不能只 --reload）
3. 重启后检查日志出现 `WSGI app 0 ready` 即加载成功

### 4.4 访问返回 400 Bad Request

**原因**：`.env` 中 `ALLOWED_HOSTS` 未包含 `${域名}`。

**修复**：加入域名后完全重启 uwsgi。

### 4.5 接口 200 但业务报错（如 40001"未读取到代理数据"）

**原因**：业务文件路径大小写与服务器实际目录不一致（Linux 区分大小写）。

**修复**：确认实际目录大小写，修正 `.env` 中的 `${代理JSON路径}`，完全重启 uwsgi。

### 4.6 nginx: [emerg] duplicate location "/"

**原因**：站点主配置里宝塔反向代理已生成 `location /`，同时又存在第二个 `location /`（如 extension 目录里自定义的 proxy.conf）。

**修复**：
```text
1. 删除多余的 location 定义文件（如 extension 目录下自定义的 proxy.conf）
2. 如需追加超时配置，写入宝塔生成的 location / 块内（见 3.4）
3. 备份主配置后修改：
   cp python_${站点}.conf python_${站点}.conf.bak-$(date +%Y%m%d)
4. nginx -t 验证 → nginx -s reload
```

在宝塔生成的 `location /` 块内追加的长任务配置示例：
```nginx
location / {
    proxy_pass http://127.0.0.1:${端口};
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Port $server_port;
    proxy_set_header Remote-Host $remote_addr;

    # 长任务超时配置（连接/读取/发送均 600 秒）
    proxy_connect_timeout 600;
    proxy_read_timeout 600;
    proxy_send_timeout 600;
    # 关闭缓冲，适合 SSE/流式响应
    proxy_buffering off;
    # 客户端请求体大小限制
    client_max_body_size 100m;
}
```

### 4.7 页面样式全乱 / 新加的 daisyUI 类名没生效

**原因**：`API/static/css/output.css` 未重新编译。Tailwind v4 只把"出现过的类"编译进产物，新增类名不重编译就不会生效；或线上未执行 `collectstatic`，页面引用的仍是旧产物。

**修复**：
```bash
# 1. 本机（项目根目录）重新编译 output.css，并提交入库
.\API\static\css\tailwindcss.exe -i API/static/css/input.css -o API/static/css/output.css

# 2. 线上收集静态文件
python manage.py collectstatic --noinput

# 3. 完全重启 uwsgi（--stop 后重新 --ini）
```
> 记住：线上**不编译** `output.css`，必须在本地编译好后提交入库。

### 4.8 切换语言没反应 / 繁体或英文页面还是中文

**原因**（按概率逐条排查）：
1. `locale` 子目录名写成 `zh-hant` 而非 `zh_Hant`（Django 静默找不到 `.mo`，**且不报错**）；
2. 改了 `.po` 没执行 `python scripts/compile_locale.py`（Django 运行时**只读 `.mo`**）；
3. 没重启 uWSGI（Django 缓存已加载的翻译目录）。

**修复**：
```text
1. 检查目录名：locale/ 下应为 en/、zh_Hant/（下划线！），写成 zh-hant 无效
2. 确认 .mo 存在且比 .po 新：ls -l locale/zh_Hant/LC_MESSAGES/
3. 重新编译词条：python scripts/compile_locale.py（本机无 gettext，不能用 compilemessages）
4. 完全重启 uwsgi（--stop 后重新 --ini，不能只 --reload）
5. 复验：访问 /lang/?lang=en 后刷新页面生效，或 /jsi18n/ 检查前端 JS 词典是否更新
```

## 五、验证流程（逐层排查）

**① 官网页面验证**（先确认页面可访问、样式与多语言正常）：

```text
1. 官网首页   curl -I http://${域名}/                 → 期望 200
2. 文档中心   curl -I http://${域名}/docs/            → 期望 200
3. 登录页     curl -I http://${域名}/login/           → 期望 200
4. 语言切换   curl -I "http://${域名}/lang/?lang=en"  → 期望 302/200，刷新后英文生效
   （可用 /jsi18n/ 检查前端 JS 多语言词典是否正常下发）
```

**② 接口逐层排查**（本机直连 → 域名直连 → 业务接口）：

```text
1. 本机直连后端  curl http://127.0.0.1:${端口}/api/...   → 期望 200
2. 域名直连      curl http://${域名}/api/...             → 期望 200
3. 业务接口      curl http://${域名}/api/...             → 期望 code: 10000 数据正常
```

> 若 1 失败 → 问题在 uwsgi/应用层；若 1 通 2 失败 → 问题在 Nginx 层。

## 六、预防措施

1. **通用环境复用**：宝塔中维护一个通用虚拟环境（装好 uwsgi + Django 等），新项目直接复用，避免重复踩环境坑
2. **uwsgi 绝对路径启动**：`nohup ${虚拟环境bin}/uwsgi --ini ...`，避免依赖 PATH
3. **新项目必查项**：uwsgi.ini 是否含 `virtualenv` / `pythonpath`；`.env` 的 `ALLOWED_HOSTS` 是否含域名；业务文件路径大小写是否正确
4. **虚拟环境清单化**：初始化时记录环境名与 Python 版本，环境变更前先备份
5. **Nginx 配置审查**：部署/改 SSL 后执行 `nginx -t`，并确认无重复 `location`；自定义配置避免与宝塔生成内容冲突
6. **配置验证**：按第五章逐层验证，发现问题按第四章节对号入座
7. **残留清理**：排查过程产生的临时脚本（tmp_*、/tmp 下的编译产物）完成后立即清理
