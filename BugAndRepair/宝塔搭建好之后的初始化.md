## 二、环境初始化（宝塔全新环境）

### 2.1 背景

宝塔面板为新装，服务器上没有任何 Python 运行环境，需要先由 AI 完成环境初始化，再部署项目。

### 2.2 初始化流程

```text
[步骤1] 确认系统信息
   → 确认 OS 版本、宝塔版本、是否已有 Python 版本管理器
   → 验证点：可正常通过 SSH 登录，宝塔面板可访问

[步骤2] 创建项目虚拟环境
   → 使用宝塔"Python 项目管理器"创建虚拟环境，或手动 venv 创建
   → 验证点：虚拟环境 bin 目录存在，python --version 输出正常
   → 【需确认】环境命名（如 ${虚拟环境名}）与 Python 版本

[步骤3] 安装项目依赖
   → 在虚拟环境内执行 pip install -r requirements.txt
   → 验证点：import django 等核心依赖无报错

[步骤4] 安装 uwsgi（重点，易失败）
   → 优先尝试 pip install uwsgi
   → 若编译失败，改用源码编译方式（见第五章 5.2）
   → 验证点：uwsgi --version 输出正常
   → 注意：必须在虚拟环境内安装，禁止污染全局环境
```

## 三、事故现象

通过 `nohup` 启动项目时持续报错：

```bash
nohup: failed to run command 'uwsgi': No such file or directory
```

服务无法启动，对外接口不可访问。

---

## 四、根因分析

### 4.1 直接原因

- 启动脚本使用 `nohup uwsgi ...`，依赖系统 `PATH` 查找命令；
- 但 uwsgi **未安装**在当前虚拟环境中，或安装位置不在 PATH 中；
- 导致 shell 无法找到 `uwsgi` 可执行文件。

### 4.2 深层原因（可能组合出现）

| 原因 | 说明 |
|------|------|
| 环境被替换 | 旧虚拟环境被删除，新环境未安装 uwsgi（本次实际原因） |
| PATH 为空 | 非交互式 SSH 会话中 PATH 为空，导致编译脚本找不到 gcc 等工具 |
| 编译失败 | `pip install uwsgi` 报 `AttributeError` 或 "you need a C compiler"，未得到 uwsgi 产物 |

### 4.3 为什么本地环境没问题

本地使用 `python manage.py runserver` 运行，无需 uwsgi；线上使用 `nohup uwsgi` 方式启动，依赖环境中的 uwsgi 可执行文件，两者对环境的依赖不同。

---

## 五、解决方案

### 5.1 修复总览

```text
1. 在虚拟环境中安装 uwsgi（失败时走源码编译）
2. 修复运行期依赖（如 libpython 共享库缺失）
3. 配置 uwsgi.ini（指定虚拟环境路径与项目路径）
4. 配置 Nginx 反向代理（含长任务超时）
5. 修复应用层配置（ALLOWED_HOSTS、文件路径大小写）
6. 完全重启 uwsgi 使配置生效
```

### 5.2 uwsgi 安装（含源码编译方案）

```bash
# 方式一：pip 安装（推荐先试）
${虚拟环境bin}/pip install uwsgi

# 方式二：源码编译（pip 失败时使用）
cd /tmp && wget https://files.pythonhosted.org/packages/.../uwsgi-2.0.28.tar.gz
tar zxf uwsgi-2.0.28.tar.gz && cd uwsgi-2.0.28

# 关键：非交互式 SSH 中 PATH 可能为空，先补齐
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
export CC=/usr/bin/gcc

# 若报 cannot find -lpython3.12，指定 Python 库路径
export LDFLAGS=-L${Python安装目录}/lib

make
cp uwsgi ${虚拟环境bin}/uwsgi && chmod +x ${虚拟环境bin}/uwsgi
```

```bash
# 运行时报 libpython3.12.so.1.0: cannot open shared object file 时：
# 将 Python 库目录写入 ldconfig 配置并刷新
echo "${Python安装目录}/lib" > /etc/ld.so.conf.d/python.conf
ldconfig
```

### 5.3 uwsgi.ini 核心配置

```ini
[uwsgi]
# 项目目录（【需确认】${项目部署路径}）
chdir = ${项目部署路径}
# WSGI 入口
wsgi-file = ${项目部署路径}/项目名/wsgi.py
callable = application
# 虚拟环境与依赖路径（必须指定，否则用系统 Python 找不到 django）
virtualenv = ${虚拟环境路径}
pythonpath = ${虚拟环境路径}/lib/python3.x/site-packages
# 进程/线程
processes = 4
threads = 2
# pid 文件
pidfile = ${项目部署路径}/uwsgi.pid
# 监听地址（【需确认】端口 ${端口}）
http = 0.0.0.0:${端口}
# 运行用户
uid = ${运行用户}
gid = ${运行用户}
master = true
buffer-size = 32768
daemonize = ${日志目录}/uwsgi.log
```

### 5.4 Nginx 反向代理

- 在宝塔"反向代理"中配置，指向 `http://127.0.0.1:${端口}`；
- 若项目含长耗时任务（如 DeepSeek 生成），将代理超时调大（建议 600s）并关闭缓冲，避免 504。

### 5.5 应用层配置修复

| 问题表现 | 原因 | 修复 |
|----------|------|------|
| 访问返回 400 | `.env` 中 `ALLOWED_HOSTS` 未包含域名 | 加入 `${域名}` |
| 业务接口返回 40001"未读取到代理数据" | `${代理JSON路径}` 大小写与服务器实际目录不一致（Linux 区分大小写） | 修正为实际路径 |
| 修改 `.env` 后仍无效 | 环境变量仅在启动时加载 | 完全停止并重启 uwsgi，不能只 --reload |

## 八、排查指南（给 AI）

### 8.1 确认 uwsgi 是否存在

```bash
# 查看当前 PATH
echo $PATH
# 查找 uwsgi
which uwsgi || find ${虚拟环境路径} -name uwsgi -type f
# 若均无 → 未安装，走第五章安装流程
```

### 8.2 区分错误层级

```text
nohup 找不到 uwsgi         → 安装/路径问题（第五章 5.2）
uwsgi 启动后 ModuleNotFoundError: django → virtualenv/pythonpath 配置缺失（5.3）
uwsgi 启动后 400          → ALLOWED_HOSTS 问题（5.5）
接口 200 但业务报错       → 业务配置问题，如文件路径大小写（5.5）
```

### 8.3 必须询问用户的信息

遇到以下任一项，**停下并提问**，不得自行假设：

1. 项目部署路径 / 虚拟环境名 / 域名 / 端口
2. 项目依赖清单是否以 requirements.txt 形式提供
3. 代理数据等外部文件的真实存放路径（含大小写）
4. 是否需要配置 HTTPS / 域名解析是否已指向本机

## 九、预防措施

1. **uwsgi 使用绝对路径启动**：`nohup ${虚拟环境bin}/uwsgi --ini ...`，避免依赖 PATH
2. **虚拟环境清单化**：初始化时记录环境名与 Python 版本，环境变更前先备份
3. **.env 规范化**：所有路径统一以项目根目录为基准，标注实际大小写
4. **配置验证**：部署后依次验证 本机端口 → 域名直连 → 业务接口，逐层排查
5. **残留清理**：排查过程产生的临时脚本（tmp_*、/tmp 下的编译产物）完成后立即清理
