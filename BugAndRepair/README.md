## 阅读顺序建议

- **要上线**：[Django部署上线操作手册.md](Django部署上线操作手册.md) → [Nginx与uwsgi配置.txt](Nginx与uwsgi配置.txt) → 手册末尾「安全加固要点」。
- **要排障**：先看 [变更记录.md](变更记录.md) 确认近期是否有相关改动，再查对应事故报告（重定向 / 静态资源）。
- **要加固**：[安全评估与整改报告.md](安全评估与整改报告.md) 的「风险总览」表 + 各项验收标准。

## 维护约定

1. **不要写入真实敏感信息**（S-11 整改要求）：公网 IP、真实域名、服务器绝对路径、账号口令、密钥一律用占位符表示，例如
   `{SERVER_IP}`、`{DEPLOY_DOMAIN}`、`{PROJECT_ROOT}`、`{PYTHON_BIN}`、`{端口}`。
2. **文档内引用代码请用仓库相对链接**（如 `../API/common/middleware.py`），不要用本机绝对路径（`file:///...`），否则在 GitHub 上无法打开。
3. **新增功能或修复缺陷**后，在 [变更记录.md](变更记录.md) 追加一条；涉及安全整改的，同步更新 [安全评估与整改报告.md](安全评估与整改报告.md) 的对应编号与状态。
4. 事故类文档建议保留**现象 → 根因 → 处置 → 预防**四段式，便于他人复盘。
