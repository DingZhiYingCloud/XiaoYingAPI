## 阅读顺序建议

- **要在本机跑起来 / 本地排障**：[本地开发环境从零搭建-踩坑与经验.md](本地开发环境从零搭建-踩坑与经验.md)（依赖与 PATH → AI Key 在库 → 红果直出运行物 → `MAC check failed` 整页 500 排障）。
- **要上线**：[Django部署上线操作手册.md](Django部署上线操作手册.md) → [Nginx与uwsgi配置.txt](Nginx与uwsgi配置.txt) → 手册末尾「安全加固要点」。**需要代练搬单时**另见**第九节**（独立项目 `X:\BanDan`：两个代练平台凭据从哪来、先 dry-run 再开自动运行、多 worker 的数据库互斥）。
- **要排障**：先看 [变更记录.md](变更记录.md) 确认近期是否有相关改动，再查对应事故报告（重定向 / 静态资源）。
- **要做推广**：[SEO外链平台清单.md](SEO外链平台清单.md)（渠道清单 → 分发节奏 → 风控红线）。
- **要加固**：[安全评估与整改报告.md](安全评估与整改报告.md) 的「风险总览」表 + 各项验收标准。

## 维护约定

1. **不要写入真实敏感信息**（S-11 整改要求）：公网 IP、真实域名、服务器绝对路径、账号口令、密钥一律用占位符表示，例如
   `{SERVER_IP}`、`{DEPLOY_DOMAIN}`、`{PROJECT_ROOT}`、`{PYTHON_BIN}`、`{端口}`。
2. **文档内引用代码请用仓库相对链接**（如 `../API/common/middleware.py`），不要用本机绝对路径（`file:///...`），否则在 GitHub 上无法打开。
3. **新增功能或修复缺陷**后，在 [变更记录.md](变更记录.md) 追加一条；涉及安全整改的，同步更新 [安全评估与整改报告.md](安全评估与整改报告.md) 的对应编号与状态。
4. 事故类文档建议保留**现象 → 根因 → 处置 → 预防**四段式，便于他人复盘。
5. **定期核对文档与代码现状**：功能 / 路由 / 脚本变更后，同步刷新 [Django部署上线操作手册.md](Django部署上线操作手册.md)、[宝塔搭建好之后的初始化.md](宝塔搭建好之后的初始化.md) 等相关段落——这类手册最容易残留**已废弃的步骤或页面路径**（如已移除的 `/admin/`、分类树 `rebuild_category_tree`、`/console/categories/`），照旧文执行会白走弯路。
