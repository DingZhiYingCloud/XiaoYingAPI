## 2026-09-11

### 修复：站点标签页图标（favicon）404

**现象**：所有页面标签页都没有图标，浏览器控制台持续报 `GET /media/favicon.ico 404`。

**根因**：`API/templates/template.html` 中早已引用 `/media/favicon.ico`（`rel="shortcut icon"` 与 `rel="bookmark"` 两处），但**该文件从未创建**——属于"模板引用了不存在的资源"，不是模板写错。

**修复**：由品牌图标 `media/images/logo.png`（1254×1254 正方形）生成多尺寸图标 `media/favicon.ico`（16 / 32 / 48），约 5 KB。模板无需改动。

**说明**：图标沿用项目既有约定放在 `/media/` 下（与 `media/images/logo.png` 等品牌资源一致），因此**不受 `collectstatic` 影响**，部署时无需额外操作——但需确认线上 Nginx 若直服 `/media/`，该目录已被正确映射。

### 2. 改造：官网表单的图形验证由阿里云切换为自研验证码

**背景**：项目此前是"有自研验证码能力（`/api/captcha_self/`），但官网表单仍用阿里云图形认证（`XYCaptcha` + 4 个参数 `lot_number / captcha_output / pass_token / gen_time`）"。本次统一改为自研模块，减少对第三方 SDK 与密钥的依赖。

**改动**

| 位置 | 改动 |
| --- | --- |
| `API/website/captcha.py` | 校验改为 `captcha_id` + `answer` 两个参数，内部调 `API/apis/captcha_self/utils.verify_challenge()`；开关改为显式 `CAPTCHA_SELF_ENABLED`（默认启用） |
| `API/static/js/captcha_auth/self/captcha-client.js` | 弹窗模式新增 `autoVerify: false`：**只收集 `captcha_id` + `answer` 并回调 `onValidate`，不调服务端校验**——验证码一次性，客户端先校验会让服务端复验必然失败 |
| `API/static/js/site/account.js` | 改用 `window.XYCaptchaSelf`；并把初始化改为**惰性**（首次提交时才取验证码，避免每次打开登录页就预取一张） |
| `account/login.html`、`register.html`、`reset_password.html` | 验证码客户端脚本换成 `js/captcha_auth/self/captcha-client.js` |
| 视图（`API/website/views.py`） | **无需改动**：5 处调用点都只依赖 `captcha.verify(request)`，接口契约未变 |

**保持不变**：阿里云线路仍作为 API 服务保留在 `/api/captcha_auth/aliyun/`（`.env` 的 `CAPTCHA_APP_ID` / `CAPTCHA_APP_KEY` 仅供该服务使用）。

**顺带修复的缺陷**：`verify_challenge()` 直接拿 `captcha_id` 做 ORM 查询，传入非 UUID 字符串时 ORM 会抛 `ValidationError` → 官网表单会返回 **500**（此前只有开放接口调用它，而接口视图层先做了 UUID 校验，所以没暴露；官网表单成为第二个调用方后立刻踩中）。已在共用函数内做格式兜底，按"验证码不存在"处理；开放接口的 `20002 参数格式错误` 语义保持不变。

**验证**

- 服务端 10 项用例：缺参数 20001 / 答案错误 20003 / 复用已用凭证 20003 / 正确答案放行（进入账号校验）/ 不存在 20003 / 非法 UUID 20003（不再 500）/ 发码·重发·重置三个接口均在**发送邮件短信之前**被拦下 / `CAPTCHA_SELF_ENABLED=false` 时跳过校验。
- 浏览器真实流程：登录页加载自研客户端（无阿里云脚本、无 `XYCaptcha` 全局）；提交弹出「安全验证」自研弹窗；填错答案 → 服务端拒绝并提示「图形验证未通过，请重新验证」；再次提交 → **自动换新图**；填对答案 → 图形验证放行，提示变为「账号或密码错误」；全程无 JS 报错，且对 `/api/captcha_auth/aliyun/`、`ct4.js` 的请求为 **0**。

### 3. 修复：文档中心在线调试调用流式接口报 500（AI / DeepSeek 的 stream=true）

**现象**：在接口文档中心用「在线调试」测试 AI 接口（`POST /api/ai/BuiltInModel/deepseek`）并把 `stream` 选为 `true` 时，调试面板返回 500，服务端日志为：

```
File "API/website/docs_views.py", line 216, in call
    raw = response.content.decode('utf-8', 'ignore')
AttributeError: This StreamingHttpResponse instance has no `content` attribute.
```

**根因**：`stream=true` 时 AI 接口返回的是 SSE 流式响应（`StreamingHttpResponse`），而在线调试代调只会按普通响应读取 `response.content` —— 流式响应没有该属性。**与 DeepSeek 服务本身无关**（同一接口 `stream=false` 正常返回）。

**修复**：代调视图读取响应体前先判断 `response.streaming`，流式响应改为消费 `streaming_content` 拼接后再解析；普通响应维持原逻辑。调试面板因此可以直接看到完整 SSE 内容（逐块 `data: {"content": ...}` 与结束标记 `data: [DONE]`）。

**影响面核查**：全项目读取响应体只有两处——本处与调用统计的 `business_code()`（其本就带 `not response.streaming` 守卫），无同类盲点；返回流式响应的接口全项目仅 AI 这一个。

**验证**：`/docs/_call/` 转发 AI 接口，`stream=false` → 200 / `application/json` / 正常回复；`stream=true` → **200**（原为 500）/ `text/event-stream` / SSE 内容完整可读且含 `[DONE]`。

## 2026-09-10

### 1. 新增：自研图形验证码服务 `/api/captcha_self/`

**背景**：项目此前只有阿里云图形认证的**集成**（`/api/captcha_auth/aliyun/`，滑块/点选由阿里云 SDK 提供，我们只做服务端二次校验），没有可自主掌控的验证码能力。

**实现**

| 层次 | 位置 | 说明 |
| --- | --- | --- |
| 生成引擎 | `SpiderServices/Captcha/generator.py` | Pillow 直接绘制 PNG，不依赖第三方服务；支持字符图片（剔除易混淆字符）与算术两类；逐字符随机颜色/角度/偏移 + 干扰线 + 噪点 + 正弦扭曲 |
| 数据模型 | `API/models/Captcha/captcha.py`（`CaptchaChallenge`，迁移 `0021_captcha_challenge`） | 一次性挑战记录：答案、类型、过期时间、used；图片不落库 |
| API 层 | `API/apis/captcha_self/` | `GET /generate`（返回 captcha_id + base64 图片 + 有效期）、`POST /verify`（一次性校验，条件更新保证并发只成功一次） |
| 前端 | `API/static/js/captcha_auth/self/captcha-client.js` | 两种形态：内联 `create()`；**弹窗模式** `init()/show()`（自包含样式、零依赖，与阿里云 SDK 弹窗的接入体验一致） |
| 文档 | `API/website/docs/captcha_self.py` | 声明式接入文档中心，`/docs/captcha_self/` 含真实弹窗联调面板 |

**关键设计**

- 答案**一次性消费**：条件更新 `filter(used=False).update(used=True)`，无论对错都作废，防同一张图被反复暴力尝试；失败后前端自动换新图。
- 弹窗样式**自包含**（注入 `.xycs-*` 前缀样式 + 强制 `position:fixed;inset:0;margin:auto` 居中）——宿主页面的 Tailwind preflight 会把 `<dialog>` 默认的 `margin:auto` 重置为 0，不显式声明就会贴左上角。
- 用户主动关闭（取消 / ×）**同步**回调 `onClose`，不依赖异步的 `<dialog> close` 事件（标签页被节流时该事件会明显延迟，曾导致状态复位时好时坏）。

**已知短板（如实记录）**：字符类验证码对现代 OCR 抵抗有限——用本项目自带的 `ddddocr` 实测识别率约 **9~10/10**。这是字符验证码的固有问题（已加旋转/扭曲/干扰也仅小幅改善）。若需强防机器，应改用滑块/点选或第三方方案（阿里云线路已接入）。

**配置**：`.env` 可选 `CAPTCHA_SELF_EXPIRE_SECONDS`（默认 300 秒）。

### 2. 实施：API 调用统计（安全报告 A-03 重新实施）

**背景**：A-03「计量统计」2026-09-04 曾以明细表 + `/admin/usage/` 实现，随 admin 下线整体回退。本次按既定口径「仅计量、不限流、含匿名、成功/失败拆分」重做。

**实现**

- **按天预聚合**：`ApiCallStat`（迁移 `0022_api_call_stat`），聚合键 = 日期 + 端点 + 项目 + 状态码，存调用次数 / 总耗时 / 最大耗时，**不落明细**（表规模可控）。
- **写入**：`API/common/api_stats.py`。进程内缓冲聚合，满 200 键或每 5 秒批量落库；多进程靠「先累加更新、无则插入」汇合；统计失败只记日志、不影响业务。
- **采集**：复用 `ApiRequestLogMiddleware`（A-05），未新增中间件。
- **查询**：`API/common/api_stats_query.py`，供三处复用同一口径。
- **展示**：
  - 超管看板 `/console/stats/`（Chart.js 本地托管，7/30 天可切；含趋势、服务/接口/项目排行、状态码分布、平均与最大耗时）
  - 文档中心每个接口卡片显示「累计调用 N 次」（服务端渲染，未登录可见）
  - 公开服务 `/api/statistics/`（`api_calls` / `services`，**只返回调用次数**，不含项目、失败率、耗时）

**顺带修复的缺陷**

1. **认证被拒的请求不进日志与统计**：`ApiRequestLogMiddleware` 原注册在 `ApiAuthMiddleware` **内层**，而认证失败由外层直接返回、不会向下调用。已把它提前到认证中间件之前（仍能读到下行阶段挂上的 `request.auth_app`）。
2. **带路径参数的接口会炸表**：music / seo 存在 `<uuid:...>`、`<int:...>` 路由，若按真实路径落库会「一个 UUID 一行」且排行被打散。改为记录**路由模板**并把参数归一为 `<param>`。

**口径**：仅 `/api/` 请求；认证被拒（20011）与未匹配路由**也计入**；统计服务自身不计入；时间按 `Asia/Shanghai` 本地日期切分。

**上线注意**：`rebuild_category_tree` 生成的新分类节点默认 `inherit`，按 fail-closed 会变成「需要认证」，**部署后需在 `/console/categories/` 把 `/api/statistics/` 设为开放**。

**未做**：配额限制与账单体系；历史调用量不回填（统计自上线起累计）。

### 3. 修复：超管页登录跳转死循环

**现象**：已登录的**普通用户**访问任一超管页（`/console/projects/`、`/console/categories/`、`/console/stats/`）时浏览器报 `ERR_TOO_MANY_REDIRECTS`。

**根因**：`superadmin_required` 把非超管跳转到 `/login/?next=<超管页>`，而登录页 GET 的判定是 `if _current_user(request) or is_admin: return redirect(next_url)` —— 「已登录的普通用户」也满足条件，于是回跳超管页 → 再被打回登录页，成环。

值得注意的是设计意图本就写在 `API/website/admin_auth.py` 的注释里（「普通用户即便回跳也进不去（防循环：普通登录一律回首页）」），只是实现漏了「已登录普通用户」这条路径。

**修复**：把「是否按 `next` 回跳」的判定从 `已登录 or 超管` 收紧为**只有超管**；已登录的普通用户一律回首页。

**验证**（逐跳跟随重定向，均 2 跳内收敛）

| 场景 | 链路 | 结果 |
| --- | --- | --- |
| 普通用户 → 超管页 | `/console/stats/` → `/login/?next=...` → `/` | 200 |
| 普通用户 → 登录页(next=超管页) | `/login/?next=...` → `/` | 200 |
| 超管 → 登录页(next=超管页) | `/login/?next=...` → `/console/stats/` | 回跳仍生效，200 |
| 匿名 → 超管页 | `/console/stats/` → `/login/?next=...` | 渲染登录页，200 |
