# 本地开发环境从零搭建：踩坑与经验（Windows）

> 适用：把仓库拉到本机后，从「装依赖 → 起服务 → 跑通各模块」的完整过程与坑位。
> 与 [Django部署上线操作手册.md](Django部署上线操作手册.md)（**线上部署**）互补：本文记的是**本地开发机**的一手踩坑。
>
> **脱敏约定**：本文不写真实 IP / 域名 / 账号 / 密钥 / 本机绝对项目路径，统一用占位符：
> `{SERVER_IP}`、`{DEPLOY_DOMAIN}`、`{PROJECT_ROOT}`、`{PYTHON_BIN}`、`{TOOLS_DIR}`（本机工具根目录，示例 `D:\DevTools`）、`{端口}`。

---

## 一、最短启动路径

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

copy .env.example .env          # 至少填 SECRET_KEY
python manage.py migrate        # 迁移随代码入库
python manage.py createsuperuser
python manage.py runserver 0.0.0.0:{端口}
```

要点：

- 登录 / 注册入口是 `/login/`、`/register/`（**没有 `/admin/`**，访问返回 404）；管理入口是官网自带的**超级管理员控制台** `/console/`。
- 启动后自查：`python manage.py check`；迁移是否干净：`python manage.py migrate --check`（退出码 0 = 无待应用迁移）。

### 坑 1：`SECRET_KEY` 缺失直接拒绝启动

`.env` 未提供 `SECRET_KEY` 时 `settings.py` 抛 `ImproperlyConfigured` 并终止（S-08 整改的 fail-closed）。
并且它**同时是 `app_secret` 等凭据密文的派生密钥** —— 上线后**不可变更**，一旦更换已入库的密文全部解不开（见第六节），务必先备份。

### 坑 2：忘了迁移 / 依赖没装

表不存在、`no such table` 之类报错先查 `migrate --check`。本机实测 Python 3.14 + Django 6.1.x 可正常跑。

## 二、外部运行时依赖（Windows 本地）

| 依赖 | 谁在用 | 缺失症状 |
| --- | --- | --- |
| **Node.js**（≥18） | 抖音评论发布、海角社区视频播放列表（本地补环境生成签名） | 调用时报权限/找不到 `node` |
| **ffmpeg** | 红果短剧第 4 集及以后「网页直出」（CENC 解密 + 转 H.264） | 第 4 集直出失败 |
| **Java**（可免） | 红果取流签名器 | 仓库内置裁剪版 JRE（**Windows 版**），本机无需另装 |

### 坑 3：装完工具后「当前终端」仍然找不到命令

把 Node/ffmpeg 装到 `{TOOLS_DIR}` 后，**已经打开的终端 / IDE agent 会话拿的是启动时的 PATH 快照**，`node -v` 仍报「不是内部或外部命令」；**必须新开终端**才生效。
若命令由**长驻服务进程**调用（如 Django 用 `subprocess` 调 `node`/`ffmpeg`），该进程继承的也是旧 PATH —— 最稳的做法：

- 用 `.env` 里的绝对路径变量兜底：`HAIJIAO_NODE_BIN`、`HONGGUO_FFMPEG_BIN`；或
- 启动服务进程时显式注入 PATH（例如 `PATH={TOOLS_DIR}\nodejs;{TOOLS_DIR}\ffmpeg\bin;%PATH%`）。

### 坑 4：包管理器默认把东西装到 C 盘

`winget` 默认装 C 盘（`C:\Program Files\...`），要装到别的盘需卸载后改用便携版或安装到指定目录。
`npm` 的**全局目录（prefix）与缓存（cache）默认都在 C 盘用户目录**，可用 `npm config set prefix/cache` 改到目标盘，避免 C 盘被慢慢吃掉：

```powershell
npm config set prefix "{TOOLS_DIR}\nodejs"
npm config set cache  "{TOOLS_DIR}\npm-cache"
```

## 三、红果短剧「网页直出」运行物（最容易漏）

**现象**：一部剧**前 3 集能播，第 4 集及以后**播不了。

**根因**：`scripts/hongguo_sign/` 下的 `sign/unidbg-sign.jar` 与 `capture/fq_oversea/*`（`libmetasec_ml.so`、`libc++_shared.so`、`ms_*.bin`）属**第三方二进制、不入库**，需单独获取后按**相同相对路径**放好（unidbg 是模拟 ARM，跨平台通用，可整目录拷贝）。

### 坑 5：本地 `.env` 里残留服务器用的 `HONGGUO_JAVA_BIN`

`HONGGUO_JAVA_BIN` 若指向 **Linux 路径**（如 `/usr/bin/java`），在 Windows 上会**覆盖内置 JRE** 导致「找不到可用的 Java」。
**本地留空即可**（留空 → 走仓库内置的 Windows 版 JRE）。自证：`{PROJECT_ROOT}\scripts\hongguo_sign\jre\bin\java.exe -version` 能打印版本。

## 四、AI（DeepSeek）配置：Key 在**数据库**里，不在 `.env`

**现象**：`.env` 里明明填了 `DEEPSEEK_API_KEY`，服务余量巡检 / AI 接口仍报「DeepSeek 未配置完整的 API Key / 上游地址」。

**根因**：AI 的厂商 / 模型 / Key 已迁到**数据库**（`AiProvider` / `AiModel` / `AiSystemPrompt`）；`.env` 里的 `DEEPSEEK_API_KEY`、`DEEPSEEK_API_URL` **已废弃**（仅历史数据迁移用过一次，迁移标记后不再读）。

**正解**：到控制台 `/console/ai/models/` 维护厂商与 Key（落库为 AES 密文，页面只回显掩码）；模型清单/对话接口即时生效、无需重启。

**验证**：调用厂商余额接口或 `/api/ai/BuiltInModel/models`、`/api/ai/BuiltInModel/chat`；本机可用管理命令直接回读 `AiProvider` 的掩码确认已配置。

## 五、QQBot（NapCat）在 Windows 本地跑起来

**结论**：Windows 用官方 **`NapCat.Shell.Windows.OneKey.zip`（一体包）** 即可，**无需单独安装 QQ**——QQ 与 NapCat 都随包内置/解压到**解压目录内**。因此只要**把解压目录放到目标盘**，就能做到「整包不落在 C 盘」。

项目自带**一键部署**（控制台 `/console/qqbot/`）会自动完成：下载 → 解压 → 写「HTTP 服务端 + 事件上报 + WebUI」配置 → 启动 → 把地址与 token 回填到设置页；**唯一人工步骤是扫码登录 QQ**。

可选配置：`PushSetting.napcat_dir` 指定安装目录；「机器人 QQ 号」用于快速登录；「事件回调基址」填实际访问域名（本地即 `http://127.0.0.1:{端口}`）。

### 坑 6：QQ 的**用户数据**默认仍写在 C 盘用户目录

一体包不会把 QQ **安装**到 C 盘，但 QQ 的**数据**默认落在 `%USERPROFILE%\Documents\Tencent Files` 与 `%APPDATA%\Tencent`。要彻底不占 C 盘，可用**目录联接（junction）**把这两个目录的实体迁到目标盘，C 盘只留联接点：

```powershell
# 停掉 NapCat/QQ 后：把实体移到目标盘，再在原位置建联接
Move-Item "$env:USERPROFILE\Documents\Tencent Files" "{TOOLS_DIR}\qqdata\Tencent Files"
New-Item -ItemType Junction -Path "$env:USERPROFILE\Documents\Tencent Files" `
         -Target "{TOOLS_DIR}\qqdata\Tencent Files"
```

### 坑 7：**同一个 QQ 号在本地与线上同时登录会互相踢下线**

本地 NapCat 用与线上**同一个机器人 QQ** 扫码后，线上实例常被判为异地登录而掉线，需到线上**重新扫码**恢复。
本地联调建议**换一个测试小号**，避免影响生产机器人的登录态。

### 坑 8：事件上报是 **chunked** 传输

NapCat 的事件上报用 `Transfer-Encoding: chunked` 发请求体，而 Django 自带 `runserver` 只按 `Content-Length` 读 body。项目已在 `runserver` 启动时**自动打补丁**（`API/common/devserver.py`），本地无需处理；生产用 gunicorn / uvicorn 或前置 nginx 会自行解开 chunked。

## 六、后台 500：一条「解不开的密文」拖垮整页

**现象**：访问后台（含列表页）直接 500，错误日志尾部是 `Crypto/Cipher/_mode_gcm.py ... ValueError: MAC check failed`。

**根因**：`API/models/Projects/app.py` 的 `EncryptedSecretField.from_db_value` 在**读库时无条件解密**。库里若存在一条用**旧 `SECRET_KEY`** 加密的遗留记录（换过密钥 / 迁移过库都可能留下），模板渲染该表时就会抛错 → **整页 500**。

**处置**（本次实测）：

1. **定位坏行**：对该表的加密字段逐行 `values_list(field)` 探测（只会触发该字段的转换器），锁定抛 `ValueError` 的行；
2. **修复**：对该行 `reset_secret()`（重新生成并用当前密钥加密；旧密文本就解不开，重置不丢可用数据），或直接删除这条残留记录；
3. **复检**：再扫一遍确认无坏行。

**经验**：`SECRET_KEY` 一旦变更，历史密文即失效。排查任何 `MAC check failed` 都按「先定位坏行 → 再重置/删除」处理；同时记得 `.env` 的 `SECRET_KEY` 必须**稳定且备份**。

## 七、验证与冒烟（本地自查）

- **接口冒烟**：仓库自带按配置逐条打 `/api/` 的冒烟脚本；缺变量的用例自动 **SKIP**，结果分 **PASS / FAIL / SKIP**，便于快速定位。基准是「HTTP 200 且业务 code 命中期望」。
- **后台页面巡检**：用 Django 测试客户端 `force_login(超管)` 后逐页 `GET`。**坑**：测试客户端默认 Host 是 `testserver`，会被 `ALLOWED_HOSTS` 拦成 **400** —— 必须显式传 `HTTP_HOST=127.0.0.1`（或加进白名单）。
- **自研图形验证码会挡住自动化登录**：本地联调 / 自动化可临时在 `.env` 设 `CAPTCHA_SELF_ENABLED=false`（`API/website/captcha.py` 读取，默认开启），**用完立即恢复**。

## 八、浏览器自动化（chrome-devtools-mcp）落地要点

- 装到非 C 盘：`npm i -g chrome-devtools-mcp`（先把 `prefix`/`cache` 指到目标盘，见坑 4）。
- 它**自带 CLI**，可不经 MCP 直接驱动 Chrome 做页面验收（`new_page` → `fill` → `click` → `evaluate_script` → `take_screenshot` → `list_console_messages`），适合排查与脚本化。
- **默认 profile 目录在 C 盘**（`%USERPROFILE%\.cache\chrome-devtools-mcp\...`），务必用 `--user-data-dir` 指到目标盘。
- 多 agent / 多窗口共用时的隔离与抢占问题，见 `.trae/rules/chrome-devtools-mcp多实例规范.md`。

## 九、其它零星坑

- **代理 IP 提取**：部分平台只对国内 IP 开放提取接口；经中转从非白名单出口访问可能直接 403（表现为上游 HTML 403 被当成解析失败）。
- **Django 单元测试**用独立文件库（`settings.DATABASES['default']['TEST']`）；测试脚本多在结束时自清数据，但不保证覆盖所有表。
- **Node 依赖只影响个别服务**（抖音评论、海角取流）；其余服务不依赖 Node。

## 十、自查清单（起服务前过一遍）

1. `.env` 有 `SECRET_KEY`（且已备份）；
2. `migrate --check` 干净；
3. 需要的话：`node -v` / `ffmpeg -version` 在**新开终端**里可见（或已配 `.env` 直指绝对路径）；
4. 红果直出：`scripts/hongguo_sign/` 运行物齐全，且 `HONGGUO_JAVA_BIN` 留空（本地走内置 JRE）；
5. AI：到 `/console/ai/models/` 确认厂商 Key 已填（**不是**看 `.env`）；
6. QQBot：NapCat 已扫码、HTTP 服务端就绪、事件回调基址正确；
7. 若报 `MAC check failed`：按第六节定位并重置坏行。
