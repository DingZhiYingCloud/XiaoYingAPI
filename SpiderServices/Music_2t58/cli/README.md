# 2T58（爱听音乐网）爬虫 CLI 使用文档

用大白话解释：这是抓取 2T58（爱听音乐网，2t58.com）的"搬运工"工具。它会按照歌手列表，把歌名、歌手、播放链接都抓下来，存成一个能直接导入小影 API 数据库的 JSON 文件。

---

## 一、怎么启动

**方式一：交互式面板（推荐新手用）**

```powershell
.venv\Scripts\python.exe SpiderServices/Music_2t58/cli/main.py
```

启动后会出现一个菜单，按数字选就行：

```
1. 抓取歌手歌曲（从第几页到第几页）
2. 重试失败任务
3. 查看输出统计
4. 导入格式预检
5. 播放源缓存管理
6. 查看日志
7. 切换站点域名
8. 补抓暂存播放源（暂停后继续搬）
0. 退出
```

**方式二：命令行（更灵活，适合脚本/批处理）**

```powershell
# 抓取歌手列表第 1-3 页
.venv\Scripts\python.exe SpiderServices/Music_2t58/cli/main.py crawl --start 1 --end 3

# 补抓暂存文件里的播放源（限量 200 首、1 线程，防封）
.venv\Scripts\python.exe SpiderServices/Music_2t58/cli/main.py resume --limit 200 --threads 1

# 其他：retry（重试失败） precheck（预检） stat（统计） cache（缓存） log（日志）
```

## 二、cli 文件夹里每个文件是干嘛的

| 文件 | 作用（大白话） |
|------|----------------|
| `main.py` | 总入口。菜单、命令行解析、各个命令的实现都在这 |
| `crawler.py` | 干活的。负责去网站抓歌手、抓歌曲、抓播放源，还有"断点续传"逻辑 |
| `storage.py` | 管文件的。读写输出文件、暂存文件、缓存文件，还有去重、统计、预检 |
| `logger.py` | 记日志的。彩色打印 + 把出错信息写进日志文件 |
| `config.py` | 集中配置。站点域名、默认线程数、默认文件路径等，改配置只改这一个文件 |
| `__init__.py` | 空文件，让 Python 把 cli 当作一个模块（不用管它） |

## 三、运行后产生的文件是干嘛的

跑完抓取后，会在 `output/` 目录产生几个文件：

| 文件 | 比喻 | 作用 |
|------|------|------|
| `music_singers.json` | **搬回来的成品** | 最终结果：每首歌带播放链接，能直接导入数据库 |
| `music_singers_pending.jsonl` | **待办清单** | 抓到了歌但还没抓到播放源的"排队名单"，防止中途崩溃丢数据 |
| `.play_url_cache.json` | **已搬记录本** | 歌→播放链接的缓存，已抓过的直接查本子，不重复请求网站 |
| `crawler.log` | **值班记录** | 所有日志和错误，出问题查这里 |

**它们的关系（搬歌流水线）：**

```
抓歌手页 ──写入──> pending.jsonl（待办清单）
                        │
              resume 补抓播放源（先查 cache，没抓到才访问网站）
                        ▼
              music_singers.json（成品，最后导入数据库）
```

- 从 `pending` 拿一首歌 → 先看 `cache` 本子 → 没有就去网站抓 → 抓到记进 `cache`、写进 `json`、从 `pending` 划掉
- 等 `pending` 空了，`json` 就是全部成果

**什么时候会产生这些文件：**
- 收集歌曲时：每抓完一个歌手，歌就实时写进 `pending.jsonl`（防崩溃丢数据）
- 补抓播放源时：抓一首记一首进 `cache`，全部处理完才统一写进 `json` 并清空 `pending`
- `cache` 和 `log` 会一直保留，`pending` 全部处理完会自动删除

## 四、防封小贴士（重要）

1. **小批量跑**：面板「8」或命令 `resume --limit 200`，一批 200~500 首，别一次跑 14 万首
2. **低线程**：`--threads 1` 最稳，赶时间再提到 2~4
3. **跑完一批歇一会**再跑下一批
4. 发现日志里大量「抓取失败/超时」= 被风控了，停一下再继续
5. **中断不丢数据**：中途 Ctrl+C 或断网都没事，已抓的都在 `cache` 里，重跑自动跳过（命中缓存不请求网站）
